Examples

Learn one thing at a time by playing a game, changing one value, then seeing the result. If this is your first alpha-star project, follow Getting started with the blank template first. It has one scene and a player you can move.

Pick puzzle if you want to focus on game rules, or platformer if you want to learn movement and collisions. Save shaders for later: they involve graphics programming in addition to TypeScript.

Step 1: create a separate example project

Open a terminal in the folder where you keep your projects, outside your current game. The command below creates a new my-platformer folder, so you can experiment without replacing your first project. A template is a ready-made project that you can edit.

npx @alpha-star/sdk init my-platformer --template platformer
cd my-platformer
npm install

npm install downloads the project's tools and engine. When it finishes successfully, stay in the my-platformer folder for the remaining commands.

Step 2: play before reading the code

npm start

You should see a small platform game. Move with Left/Right or A/D, jump with Space, and restart with R. Try collecting a coin and reaching the end. Close the game window when you are done.

Step 3: make one visible change

Open src/main.ts in your editor. Find the background line inside config and replace just that line with:

background: "#1d2b53", // A dark blue sky; the value is a hexadecimal color.

Save the file, then run npm start again. Expected result: the sky is dark blue, and the player still moves and jumps. This small change confirms you are editing the right project.

Next, open src/tuning.ts. These are the numbers that control how the game feels. Change one number at a time and play again, so you can tell which change caused the difference.

Step 4: check your changes

npx alpha check
npm test

The first command checks TypeScript for mistakes. The second runs the game's automated tests without opening a game window. Both should finish successfully after the background change. If a later gameplay change fails a test, read what the test expected before changing the test: it may have caught an accidental change to the rules.

Step 5: follow one behavior through the files

  • Start at src/main.ts: find the controls, the first scene and the assets.
  • Open src/scenes/play.ts: find what happens in enter and update.
  • Follow one imported prefab in src/prefabs/: it describes an object created by the scene.
  • Open test/main.test.ts: read a test to see a rule the game promises to keep.

You do not need to understand every file before changing the game. For the names above, see Concepts. Then choose a guide for the behavior you want to add: Input, Physics or Game UI.

Feature map for all six games

The repository's examples/ folder has six complete games, each with tests and an AGENTS.md file explaining the project to coding assistants. Placeholder art is generated by scripts in tools/ (CC0) or drawn from shapes; bundled fonts have their own license files. Five games are available as alpha init templates. blank is an additional starter template; flappy is available in the repository only.

Running an example from a repository checkout

Use this route if you already have the alpha-star source code. Start in the repository root, then enter the example folder:

cd examples/shmup
npm install
npm test
npm start

For a new project without a repository checkout, use alpha init as shown above instead. You can preview the games in the showcase before choosing one.
